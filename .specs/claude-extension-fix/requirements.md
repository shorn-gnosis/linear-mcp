# Requirements Document

## Introduction

The Linear MCP server for Claude Desktop is experiencing validation errors during the packaging process with the dxt tool. The manifest.json contains conflicting server configuration keys that are being rejected by the dxt validator, preventing successful packaging and installation of the Claude extension. This feature aims to fix the manifest schema issues and establish a reliable packaging workflow.

## Requirements

### Requirement 1

**User Story:** As a developer, I want the Linear MCP extension to package successfully with dxt, so that I can install and use it in Claude Desktop without validation errors.

#### Acceptance Criteria

1. WHEN the dxt pack command is executed THEN the manifest.json SHALL validate without schema errors
2. WHEN the extension is packaged THEN the resulting .dxt file SHALL be installable in Claude Desktop
3. WHEN the manifest is generated by dxt init THEN no manual server configuration keys SHALL be added that conflict with the schema

### Requirement 2

**User Story:** As a developer, I want the Claude extension to properly initialize with environment variables, so that the Linear API token can be configured through the extension settings.

#### Acceptance Criteria

1. WHEN the extension is installed in Claude Desktop THEN the LINEAR_ACCESS_TOKEN environment variable SHALL be configurable through extension settings
2. WHEN the server starts THEN it SHALL accept both LINEAR_API_KEY and LINEAR_ACCESS_TOKEN environment variables
3. WHEN no token is provided THEN the server SHALL start without crashing and log appropriate warnings

### Requirement 3

**User Story:** As a developer, I want the server to handle initialization gracefully, so that the extension remains stable even when authentication fails or is missing.

#### Acceptance Criteria

1. WHEN the server boots THEN it SHALL complete initialization without blocking on authentication
2. WHEN authentication fails during warmup THEN the server SHALL log the error but continue running
3. WHEN tools are called before warmup completes THEN the server SHALL wait for warmup with a reasonable timeout
4. WHEN warmup times out THEN tool handlers SHALL handle missing authentication appropriately

### Requirement 4

**User Story:** As a developer, I want a reliable packaging workflow, so that I can consistently build and deploy the Claude extension without manual manifest editing.

#### Acceptance Criteria

1. WHEN dxt init is run THEN it SHALL generate a clean manifest with only dxt-supported keys
2. WHEN the extension needs to be rebuilt THEN the process SHALL use the dxt-generated manifest as the source of truth
3. WHEN metadata needs to be updated THEN only name, id, description, and version fields SHALL be modified
4. WHEN server configuration is needed THEN it SHALL be handled through the entry point script rather than manifest keys

### Requirement 5

**User Story:** As a developer, I want proper logging and error handling, so that I can troubleshoot issues when the extension fails to work in Claude Desktop.

#### Acceptance Criteria

1. WHEN the server starts THEN it SHALL log boot progress to stderr for debugging
2. WHEN errors occur during initialization THEN they SHALL be logged with sufficient detail for troubleshooting
3. WHEN the extension is installed in Claude Desktop THEN logs SHALL be accessible through Claude's extension interface
4. WHEN the server exits unexpectedly THEN the cause SHALL be logged before termination
